📊 Chart Types

Every chart in Tableau is a specific arrangement of pills on shelves. Once you can read a chart as "this pill here, that pill there", you can build any of them from memory — and Show Me stops being a crutch.

📖 Terms on this page

Defined before they're used. Every term on the site is also in the glossary.

Mark type
The shape your data points take — bar, line, circle, square, text, map.
Example: The dropdown at the top of the Marks card. Automatic lets Tableau pick.
Crosstab / text table
A chart made of numbers in a grid rather than shapes.
Example: Region down the side, Category across the top, Sales in the cells.
Dual axis
Two measures overlaid in one space with two separate axes, so each can use a different mark type.
Example: Sales as bars with Profit Margin as a line on top.
Synchronize axis
Forcing both axes of a dual-axis chart onto one shared scale.
Example: Correct for Sales and Profit (both dollars); wrong for Sales and a percentage.
Small multiples
The same chart repeated once per category on a shared scale.
Example: Four little sales trends, one per region, instead of four tangled lines.

🧾 Every chart is a recipe

Charts in Tableau aren't types you select — they're what emerges from where you put things. The same three pills in different positions produce different charts.

ColumnsRowsMarksResult
SUM(Sales)CategoryBarHorizontal bar chart
CategorySUM(Sales)BarVertical column chart
MONTH(Order Date)SUM(Sales)LineTime series
SUM(Sales)SUM(Profit)Circle + DetailScatter plot
CategoryRegionSquare + ColorHighlight table
The pattern behind the pattern

Two dimensions → a table or crosstab. One dimension + one measure → a bar chart. A date + a measure → a line. Two measures → a scatter. Learn those four and you can predict what Tableau will build before you drop the pill.

What about three, four or seven measures?

Every recipe above tops out at two. Adding a third measure pill gives you a third separate axis rather than a third column — which is why a simple table of five metrics feels impossible at first. That needs two special generated fields, covered next in Measure Names & Values.

Too many lines? Use small multiples

Instead of seventeen coloured lines, drag the dimension to Rows so each gets its own miniature chart on a shared scale. Far easier to read, and Tableau builds it as fast as the tangled version.

🧱 Composition — stacked bars and pies

Stacked bar

Columns: SUM([Sales])
Rows:    [Region]
Color:   [Category]

// For 100% stacked, add a table calc:
Right-click SUM(Sales) →
  Quick Table Calculation → Percent of Total
  Compute Using → Table (across)

Shows totals and their mix at once. Only the bottom segment sits on a common baseline, so keep it to three or four categories.

⚖️ Dual axis — two measures, one view

  1. Build the first measure

    MONTH(Order Date) on Columns, SUM(Sales) on Rows.

  2. Add the second to the same shelf

    Drag SUM(Profit) onto Rows next to Sales. You get two stacked charts.

  3. Turn on Dual Axis

    Right-click the second pill → Dual Axis. The two charts overlay, and the Marks card splits into one section per measure.

  4. Set different mark types

    Click SUM(Sales) in the Marks card → Bar. Click SUM(Profit) → Line. Now you have bars with a line over them.

  5. Decide about synchronising

    Right-click the right axis → Synchronize Axis to put both on one scale.

Not synchronised

The line sits right on top of the bars, implying profit tracks sales almost perfectly. It's an artefact — each axis was stretched to fill the same height.

→
Synchronised

The truth: profit is a thin sliver of sales. Same numbers, honest proportions.

⚠️ Unsynchronised axes can lie

With independent scales, Tableau fits each measure to the available height. Profit ($286K) and Sales ($2.3M) will appear to track each other closely even when they don't — because the axes were stretched to make them fit.

Synchronise when the measures share units (Sales and Profit are both dollars). Don't when they don't (Sales and Profit Ratio) — but then label both axes clearly, because the reader has no other way to tell.

📶 Distributions — the charts that show spread, not averages

Bar charts show totals and averages, and both hide the thing that often matters most: whether the numbers behind them are consistent or wildly uneven. These four are how you find out.

A box plot draws the middle 50% as the box, the median as the line inside it, and anything past 1.5 × that range as its own dot. That last part is the whole point: outliers stop being absorbed into an average and become visible objects.

Histogram

Right-click [Sales] → Create → Bins
Columns: [Sales (bin)]   // blue, discrete
Rows:    CNT([Sales])      // how many orders per bucket

// Then, always:
Right-click the bin pill → Show Missing Values

Show Me builds this in one click and creates the bin for you — but it won't turn on Show Missing Values, so an empty bucket silently closes the gap and the shape comes out wrong. See Bins.

Box plot

Columns: [Region]
Rows:    SUM([Sales])
Detail:  [Order ID]      // one mark per order
Marks:   Circle

// Then drag Box Plot from the Analytics pane

The box needs individual points to summarise, which is why something has to be on Detail — or Aggregate Measures turned off. A box plot over four marks tells you nothing.

Dot / strip plot

Columns: SUM([Sales])
Rows:    [Sub-Category]
Detail:  [Order ID]
Marks:   Circle, opacity ~50%

Every order as a dot on its category's line. Shows clustering and outliers a bar chart averages away. Drop the opacity so overlaps read as density.

Control chart

Columns: MONTH([Order Date])  // green
Rows:    SUM([Sales])
Marks:   Line

// Analytics pane → Distribution Band
//   ±2 standard deviations, scoped to the table

Turns "that month looks high" into "that month is outside the band". On skewed data use percentile bands instead — see the Analytics pane.

🧩 Part-to-whole, beyond the pie

Treemap
Dimension on Detail, measure on Size and Color. Add a second dimension for nested blocks. Good for many categories where a bar chart would need scrolling — but area is hard to compare precisely, so use it for structure, not ranking.
Packed bubbles
Mark type Circle, dimension on Detail, measure on Size. Eye-catching and genuinely hard to read — no shared baseline, no axis. Fine as a way in to a dashboard, poor as the analysis.
Waterfall
Mark type Gantt Bar, a running total of the measure on Rows, and the negated measure on Size. Each bar starts where the last finished. The right chart for "how did we get from last year's number to this year's".
Sparklines
A line chart with the dimension on Rows, axes hidden and the rows squashed short. Shape only, no numbers — pair each row with a KPI value beside it and you have a scorecard that shows both level and direction.
Funnels are usually a sorted bar chart wearing a costume

The tapering-funnel look is built from a dual-axis area chart with one axis reversed, and it costs real accuracy: the taper encodes the same number twice and the eye reads the width, which is half the value. Unless the audience specifically expects a funnel, a sorted bar chart with a drop-off percentage beside each stage answers the same question and can be read exactly.

🎓 Charts Show Me won't build for you

Bar-in-bar

Actual vs target in one bar. Dual axis with both as Bars, synchronised, then narrow the front bar with the Size slider.

Lollipop chart

Dual axis on the same measure: one as Bar sized very thin, one as Circle. Cleaner than bars when you have many categories.

Bullet chart

Show Me has one, but building it manually — a bar plus a reference line for target plus distribution bands — gives far more control.

Pareto chart

Sorted bars with a cumulative-percentage line on a dual axis. Reading across to where the line hits 80% tells you how few categories account for most of the total. Needs two table calculations — a running sum and a percent of total.

Small multiples

Put a dimension on Rows and Columns alongside your measures. One small chart per combination, shared scale.

Donut chart

Two pies on a dual axis — the front one white and smaller. Fiddly, but it lets you put a KPI in the middle.

Dual axis is the universal escape hatch

Most "how did they build that?" Tableau charts are a dual axis with different mark types and some size trickery. When a chart you want isn't in Show Me, the answer is usually two measures on one axis.

💡 Show Me — useful, with a caveat

Select fields, open Show Me (top right), and available chart types light up while impossible ones grey out. Hovering any option spells out what it needs — "1 or more Dimensions, 2 Measures" — so the panel doubles as a reference for what each chart type requires.

✓ Good for

  • Learning what each chart needs
  • Quickly trying alternatives
  • Getting unstuck

⚠️ Limits

  • Rearranges your shelves, sometimes destructively
  • Only knows standard charts
  • Optimises for "valid", not "clear"

Use it while you're learning; build by hand once you know the recipes. Placing pills deliberately gives you a view you can reason about and fix — Show Me's arrangement is sometimes surprising.

📋 What each chart actually needs

Hovering a Show Me option spells out its requirement — "1 or more Dimensions, 2 Measures". That text is the most useful reference in Tableau and almost nobody reads it, so here are the common ones collected. When something is greyed out, this table says what to add.

ChartNeedsNote
Text table1+ dimensions, 1+ measuresAlways available; the fallback when nothing else fits
Bar / stacked / side-by-side1+ dimensions, 1+ measuresSide-by-side needs the dimension to split into groups, so at least two
Highlight table1+ dimensions, 1 measureTwo dimensions is the useful case — one per axis
Heat map1+ dimensions, 1–2 measuresSize encodes the first measure, colour the second
Line (continuous)1 date, 1+ measuresGreyed out without a real date field. A text date is the usual culprit
Dual line / dual combination1 date, exactly 2 measuresSelect both measures before opening Show Me
Scatter plot2–4 measuresAdd a dimension to Detail afterwards, or you get one dot
Histogram1 measureCreates the bin field for you
Box-and-whisker0+ dimensions, 1+ measuresNeeds enough marks to summarise — put something on Detail
Bullet graphExactly 2 measures, 0+ dimensionsField order decides which becomes the target. Swap with Swap Reference Line Fields
Gantt1 date, 1+ dimensionsA duration measure on Size gives the bars length
Treemap / packed bubbles1+ dimensions, 1–2 measuresSize then colour
Symbol map1 geographic dimension, 0–2 measuresThe globe icon must be on the field — see Maps
Filled map1 geographic dimension, 0–1 measuresNot available for point-level roles like latitude/longitude pairs
Greyed out is a diagnosis, not a dead end

Three causes cover nearly all of them: the wrong number of fields selected (Ctrl-click to select more in the Data pane before opening the panel), a date that isn't a date (check the icon — see field types), or a field that isn't geographic. Read the requirement text under the greyed icon and it will name which.

🧠 Key intuitions

  • Charts are recipes, not types you pick
  • Dimension + measure = bar; date + measure = line; two measures = scatter
  • Scatter plots need something on Detail — otherwise one dot
  • Always sort bar charts by value
  • Horizontal bars for long labels
  • Blue vs green dates decide seasonality vs trend
  • Dual axis: synchronise when units match, label clearly when they don't
  • Too many lines → small multiples
  • Dual axis is how the fancy charts are made
  • Distributions need individual marks — box plots and dot plots want something on Detail
  • Show Missing Values on every histogram — empty buckets otherwise vanish
  • Read the requirement text under a greyed-out Show Me option; it names what's missing

🎯 Practice exercises

  1. Bar chart: Profit by Sub-Category, sorted descending — how many lose money?
  2. Line chart: Sales by Month with a separate line per Region
  3. Switch that date pill between blue and green Month and explain both results
  4. Scatter: Discount vs Profit Ratio, coloured by Category, with Sub-Category on Detail
  5. Dual axis: Sales as bars and Profit as a line over time — synchronise the axes and explain whether you should
  6. Highlight table: Sales by State and Category using Square marks
  7. Stacked bar: Sales by Region split by Segment
  8. Convert that to 100% stacked with a Percent of Total table calculation
  9. Pie chart: Sales by Region — then rebuild it as a bar chart and say which reads better
  10. Small multiples: monthly sales trend with one row per Region
  11. Bar-in-bar: Sales vs Profit by Category on a dual axis, both as bars
  12. Select Category and Sales, then click through every enabled option in Show Me — and hover three greyed-out ones to read what they need
  13. Histogram: bin Sales, count the orders, and turn on Show Missing Values
  14. Box plot of order values by Region, with Order ID on Detail
  15. Waterfall: monthly profit as a Gantt bar with a running total on Rows and the negated measure on Size
  16. Treemap of Sales by Sub-Category nested inside Category — then rebuild it as a sorted bar chart and say which you'd present
🏆 Challenge: the same question, four ways

Take one question — "how do our categories perform across regions?" — and answer it with a grouped bar chart, a stacked bar, a highlight table and small multiples. Put all four side by side and decide which you'd actually present, and why. Each one makes a different comparison easy: grouped bars for ranking regions within a category, stacked for each region's total and mix, a highlight table for exact values, small multiples for the shape of each region on a shared scale. The right choice is whichever matches the comparison your audience needs to make.
