🗺️ Maps

Tableau can map common geographic fields without coordinates. Use maps to show location, and choose the map type carefully so the visual encoding does not mislead.

📖 Terms on this page

Key terms are defined here before they appear in the lesson. You can also find them in the glossary.

Geographic role
The location type Tableau assigns a field so it knows how to place it.
Example: State, City, Postal Code. Shown by a small globe icon.
📍 Right-click a field → Geographic Role
Generated field
A field Tableau creates that isn't in your data.
Example: Latitude and Longitude appear automatically once a field has a geographic role.
Geocoding
Looking up where a place name sits on the map.
Example: Tableau does this from a built-in database — no coordinates needed.
Choropleth / filled map
Regions shaded by value.
Example: States coloured by profit margin. Best for rates, since area distorts raw counts.
Symbol map
Circles placed at locations, usually sized by a measure.
Example: Cities sized by sales. Better than a filled map for raw totals.

🤔 When to use a map

A map answers where. If your real question is how much, a sorted bar chart will answer it faster and more precisely.

✓ Use a map when
  • Spatial position is part of the insight — clusters, adjacency, distance
  • The audience thinks geographically (territory managers)
  • You're showing coverage or gaps
  • Routes or flows between places matter
✗ Use a bar chart when
  • You want a ranking — which states sell most
  • Precise comparison matters
  • Only a handful of places are involved
  • The pattern isn't geographic at all
Area is not value

On a US map, Montana is enormous and Rhode Island is a speck — regardless of their sales. A filled map inherently over-weights large, often sparsely-populated regions. That's fine when you're showing where something happens, and misleading when you're showing how much.

If Tableau doesn't recognise a field

Right-click it → Geographic Role → pick the correct type. Common causes:

  • The column is named something unexpected
  • Codes rather than names ("CA" instead of "California")
  • It was read as a number — postcodes especially

Superstore's Country, State, City, Postal Code and Region are all detected automatically.

Have real coordinates? Set one field's role to Latitude and another's to Longitude, then put them on Rows and Columns as continuous measures. That's how you map anything Tableau doesn't have built-in geocoding for.

🎨 Map types

Filled map (choropleth)
Regions shaded by value. Best for rates and ratios — profit margin, sales per capita.
Symbol map
Circles sized by value. Best for raw totals — area doesn't distort the comparison.
Dual-axis map
Filled states plus city bubbles. Region context and point detail in one view.
Density map
Marks type → Density. For thousands of overlapping points where individual dots are unreadable.
Use filled maps for rates and symbol maps for totals

A dark fill for California sales often reflects its population more than performance. A filled map is more informative for a rate such as profit margin; use sized symbols to show raw totals.

🌈 Colour on maps

Sequential

One direction, low to high. Sales, quantity, population.

Diverging

A meaningful midpoint. Profit and loss, above and below target.

Categorical

Unordered groups. Region, segment, territory owner.

⚠️ Center a diverging palette on zero

For Profit, Tableau centers the palette on the midpoint of the data by default. If every state is profitable, the least profitable states can still appear red, suggesting losses that do not exist.

Fix: Color → Edit Colors → Advanced → select Center and enter 0.

🗂️ Layers and styling

Map → Background Maps → Light / Dark / Streets / Satellite

// Turn map features on and off

                   Streets, Terrain, Zip code boundaries

// Data layers — free US demographic context
Map → Map Layers → Data Layer →
   Population, Median Household Income, Age…

// Lock the zoom so viewers can't get lost
Map → Map Options → uncheck Pan and Zoom
Strip the map back

Roads, city names, and terrain can compete with the data. Remove unnecessary layers; coastlines and borders are often enough. The map should support the data, not compete with it.

Dual-axis maps

  1. Build the base layer

    Double-click State, set Marks to Map, put SUM(Profit) on Color.

  2. Duplicate the Latitude pill

    Hold Ctrl / ⌥ and drag Latitude to create a second copy on Rows. You now have two stacked maps.

  3. Make it dual axis

    Right-click the second Latitude pill → Dual Axis. The maps overlay, and the Marks card splits in two.

  4. Style each layer separately

    Set the second Marks card to Circle, swap State for City on Detail, and put SUM(Sales) on Size. Filled states with city bubbles on top.

⚠️ Unknown locations

A grey indicator such as “42 unknown” in the lower-right corner means Tableau could not place some values. Those rows are excluded from the map and any totals shown there.

Why it happens

  • Misspellings and inconsistent naming
  • Ambiguous city names — there are 30-odd Springfields
  • Abbreviations Tableau doesn't recognise
  • Missing country context on an international dataset

How to fix it

  • Click the indicator → Edit Locations
  • Match unrecognised values manually
  • Set the correct country/region context
  • For cities, put State on Detail to disambiguate
Check unknown locations before publishing

Unknown locations are not plotted. If 200 rows fail to geocode, the map excludes them from its totals. Check the indicator and compare the map total with a bar chart of the same measure.

Corrections made in Edit Locations live in this workbook. The same misspelling in next month's file has to be matched again, and a colleague rebuilding the view starts from scratch. If the same handful of names keep failing, fix them where the data comes from — or build a group that merges the variants, which at least travels with the data source.

🧩 Custom territories

Sales territories often do not match administrative boundaries. For example, a delivery zone may contain several states or postal codes. Tableau can create a territory from geographic areas it already recognizes.

  1. From a group — when you can list the members

    Select the states that belong to a territory and click the paperclip in the tooltip. Tableau creates a grouped geographic field by merging their outlines. You can use it like any other geographic field.

  2. From a field — when the data already says which territory

    If a column already holds the territory name, right-click it → Geographic Role → Create From → State. Tableau builds each territory's shape by dissolving the boundaries of the states inside it.

Both approaches merge existing boundaries, so a territory can only be built from whole units of a geography Tableau knows. A territory that splits a state down the middle needs a spatial file instead.

🛰️ Spatial data

Built-in geocoding only covers locations Tableau recognizes. For custom boundaries such as store catchments, school districts, or a warehouse floor plan, provide the geometry yourself.

Spatial files

Connect directly to Shapefile, GeoJSON, KML, MapInfo or TopoJSON. Tableau creates a Geometry field; put it on Detail with the mark type set to Map and the shapes draw themselves.

Latitude / longitude columns

Set one field's role to Latitude and another's to Longitude, then put them on Rows and Columns as continuous measures with AVG — or use MAKEPOINT below. Works for anything with coordinates.

Spatial joins

On the Data Source page, join two spatial sources with the Intersects operator — "which district is each store in?" answered without a lookup table.

Background images

Map → Background Images. Supply an image and its X/Y ranges to plot data on a stadium, shop floor, or circuit board. This uses a coordinate space rather than geography.

// Build a point from coordinate columns
MAKEPOINT([Latitude], [Longitude])

// Draw a line between two points — origin/destination flows
MAKELINE(MAKEPOINT([Origin Lat], [Origin Lon]),
         MAKEPOINT([Dest Lat],   [Dest Lon]))

// Distance between two points, in the unit you name
DISTANCE([Store Point], [Customer Point], "km")

// A circle of a given radius — catchment areas
BUFFER(MAKEPOINT([Lat], [Lon]), 5, "km")

Unlike the older dual-axis map trick, layers aren't limited to two, can be reordered, hidden individually, and set not to accept selection so a background layer stops swallowing clicks.

Marks layers — several map layers, independently controlled

Drag a second geographic field onto the view and Tableau offers an Add a Marks Layer drop zone. Each layer gets its own Marks card, its own mark type and its own colour — territories underneath, stores on top, delivery routes over both. Layers can be reordered, hidden, and set not to accept selection so a background layer doesn't intercept clicks.

This replaces the older dual-axis-map trick for most purposes, and unlike a dual axis it isn't limited to two.

Tableau Public and spatial files: spatial file connections work, but everything published has to become an extract — and a detailed boundary file can make that extract very large. Simplify the geometry upstream if a published map is slow to load.

🧠 Key intuitions

  • Double-click a geographic field — fastest map there is
  • Maps answer "where", not "how much" — bar charts rank better
  • Filled maps for rates, symbol maps for counts
  • Area distorts — big empty states dominate a choropleth
  • Centre diverging palettes on zero manually, every time
  • Latitude and Longitude are generated — you never make them
  • Put State on Detail for city maps to resolve ambiguity
  • Always check the unknown-locations indicator
  • Custom territories merge boundaries Tableau already knows
  • Marks layers beat dual-axis maps — more layers, each independently controlled
  • Spatial files and MAKEPOINT cover everything the geocoder doesn't
  • Strip the background — the map isn't the chart

🏆 Challenge: where should we stop discounting?

Build a map coloured by profit margin (not profit) with bubble size showing sales volume — so you can see states that sell a lot but earn little. Add average discount to the tooltip. Then find the states where high volume meets negative margin, and check whether discount explains it. Pair the map with a sorted bar chart of the worst offenders, because the map shows where and the bar chart shows how bad. Neither answers the other's question: you can't read a ranking off shaded states, and you can't see that the bad states are clustered from a bar chart.
