🗃️ Sorting, Groups & Sets

Raw fields rarely match the way you want to analyse them. Seventeen sub-categories are too many to read; a continuous Sales column needs buckets; "our top 20 customers" needs to be a thing you can filter by. Groups, sets, hierarchies and bins are how you reshape dimensions without touching the data.

📖 Terms on this page

Defined before they're used. Every term on the site is also in the glossary.

Group
Several members of a dimension merged into one. A fixed, hand-picked list.
Example: Combining East and West into "Coastal".
Set
A dimension split into In and Out, usually by a rule that re-evaluates itself.
Example: "Top 20 Customers by Sales" — put it on Color to compare them against everyone else.
Bin
A measure sliced into equal-width ranges, turning it into a dimension.
Example: Sales binned into $100 buckets, then counted — that's a histogram.
Hierarchy
Dimensions nested so you can drill down with a + on the pill.
Example: Category → Sub-Category → Product Name.
Alias
A display name for a dimension member. Changes the label only, not the data.
Example: Renaming "Office Supplies" to "Office" when the column is narrow.

🔠 Sorting — and why the default is wrong

Tableau sorts alphabetically by default. Alphabetical order almost never reflects what matters, and it forces the reader to do the ranking your chart should have done for them.

You can only sort a discrete field

Sorting rearranges members, and only a blue pill has members. A continuous axis is already ordered by its own values — there is nothing to rearrange, which is why Sort is greyed out on a green pill. To flip an axis's direction use right-click the axis → Edit Axis → Reversed instead. See what blue and green gate.

Five places a sort can come from

MethodHowScope & durability

Sorting by a field that isn't on the chart

Sort → By Field offers every field in the source, not just the ones in the view. That's how you show Sales but rank by Profit, or order Ship Mode by a numeric CASE calculation so it runs Same Day → First Class → Second Class → Standard instead of alphabetically. Build the sort field once, set it in Default Properties, and every future sheet inherits the right order.

Quick sort is fragile inside dashboards

A toolbar quick sort is computed from whatever is currently in the view, so a dashboard filter action can silently change what it means. Sort → By Field is an explicit definition that survives filtering. And if a sort seems stuck, look for the Clear Sort button on the toolbar — an old quick sort left on a pill outranks the one you just set.

🪆 Nested sorts — why every pane comes out in the same order

Put Region on Columns and Sub-Category on Rows, then sort by Sales. Every region shows its sub-categories in the same order — the national one. Nobody asked for that, and the reason is worth understanding because it comes up constantly.

A sort belongs to the dimension, not to the pane

Sorting Sub-Category produces one ordering of the seventeen members, applied everywhere they appear. It is a property of the field in that view, not of each little chart. So a per-pane ordering — West's best sellers first in West's column, East's in East's — is not something an ordinary sort can express.

In the top chart every bar length is correct — only the ordering is borrowed from the other pane. That's what makes it so easy to ship without noticing.

Two ways to get the right-hand version

  1. The Nested option in the Sort dialog

    Recent versions of Tableau add Nested alongside Alphabetic, Field and Manual. It sorts the inner dimension within each pane of the outer one. One click, and the right answer for most cases.

  2. A rank table calculation, for full control

    Create RANK(SUM([Sales])), make it discrete, and drop it on Rows to the left of Sub-Category. Set Compute Using to restart in each pane, then right-click its header → untick Show Header. The rank pill orders the rows and then hides itself.

The table-calc route is more work but it is the only one that also lets you sort by something computed — a running total, a percent difference, a rank of a rank. It is also the version that keeps working when the sort has to respond to a dashboard filter in a specific way.

Why bother

  • Viewers can explore without you building extra sheets
  • Order Date already ships as one — Year → Quarter → Month → Day

The mechanics, in full

TaskHow
Create oneDrag a field onto another in the Data pane, then name the hierarchy
Add a levelDrag another field into it. Position in the list is the drill order
Reorder levelsDrag within the hierarchy. Getting this wrong drills City → State, which reads as nonsense
Remove a levelDrag the field out, or right-click it → Remove from Hierarchy
Delete the hierarchyRight-click the folder → Remove Hierarchy. The fields survive untouched
Drill down / up in a viewThe ⊞ / ⊟ on the pill, or right-click a header → Drill Down
Three things a hierarchy doesn't do
  • It doesn't group your filters. Each level still filters independently; a Region filter does not restrict what a State card offers unless you set that card to All Values in Hierarchy.
  • It doesn't hide the fields. Category is still usable on its own — the hierarchy is an arrangement of the Data pane, not a new field.
  • It doesn't keep the mark count down. Drilling adds a pill, so 3 categories become 3 × 17 nested headers. On a slow data source, one careless drill is the whole delay.

On a dashboard, drilling changes the view for everyone looking at it. If you want controlled exploration instead, use a parameter or a filter action — see Dashboards.

📦 Groups — combine members together

A group merges several values of a dimension into one. Select the members in the view (Ctrl-click), then click the paperclip icon — or right-click the field → Create → Group.

Select members in the view with Ctrl-click, then click the paperclip icon in the tooltip. The original field is untouched — you get a new grouped field beside it.

What groups are good for

  • Consolidating the long tail — an "Other" bucket for everything below a threshold
  • Fixing inconsistent data — merging "USA", "U.S.A." and "United States" into one member
  • Ad-hoc business groupings — combining regions into "Coastal" and "Inland"
  • Simplifying a colour legend — twelve colours become four

The Edit Group dialog

  • Group / Ungroup — select members, press Group. Every ungrouped member stays itself.
  • Rename — the group's name is what appears on the chart, so name it for the reader: "Coastal", not "Group 1".
  • Include "Other" — a checkbox at the bottom left. Everything you didn't explicitly group is swept into a single Other member. This is the one setting that decides how the group ages.
  • Find — searches the member list. Indispensable when the field has hundreds of values.
  • Select two fields in the Data pane before choosing Create → Group and you get a group defined on the combination of both.
Groups are static — and "Include Other" decides how they fail

A group is a fixed list of members. When a new sub-category appears next quarter:

  • Include Other ON — it lands in "Other". The chart stays complete and the totals stay right, but the new thing is invisible inside a bucket.
  • Include Other OFF — it appears as its own bar, unnamed and unstyled, sitting outside your careful four-way split.

Neither is wrong; both are surprises unless you chose. For anything rule-based — "everything under $10k" — use a calculated field or a set instead, so it updates itself.

A group is a new discrete dimension sitting beside the original — so it has members, and everything discrete fields can do applies: tick it in a filter, put it on Color, sort it, alias it. The original field is never modified.

🏷️ Aliases — renaming members without changing them

An alias changes what a member is called. It does not change the value, merge anything, or create a field. "Office Supplies" can display as "Office" in a narrow column while the data underneath is untouched.

Right-click a dimension in the Data pane → Aliases… for the full list, or right-click a header in the view → Edit Alias for one.

This is the distinction that matters when data is dirty: an alias makes the chart look tidy while leaving the split intact. Only a group fixes the arithmetic.

Alias — one member, new label

"CA" displays as "California". Still one member, still the same rows. Nothing is combined.

Group — several members, one new member

"USA", "U.S.A." and "United States" become one bar. The numbers add together.

Calculations don't know about aliases

Alias "East" to "Eastern Region" and every chart relabels — but IF [Region] = "Eastern Region" returns nothing, because the stored value is still "East". Aliases are a display layer sitting on top of the data, and calculations, filters written by hand, and dashboard actions all work underneath it. Whenever a calculation mysteriously matches nothing, check whether you're comparing against a label rather than a value.

Aliases only exist for discrete dimension members — there is nothing to rename on a continuous axis. They're stored per data source, so they follow the field to every sheet. And they can't fix inconsistent data: three spellings aliased to the same word still produce three separate bars. That's a group.

📊 Bins — turn a measure into buckets

Bins convert a continuous measure into a discrete dimension by slicing it into equal-width ranges. This is how you build a histogram.

Right-click a measure → Create → Bins → set the bin size.

Bin labels are the lower bound

A bin labelled 200 with a size of 100 holds everything from 200 up to but not including 300. Readers routinely assume the label is the midpoint or the top. If the chart is going to anyone else, say so in the axis title — "Order value (lower bound of $100 band)" — or build named bands with a calculated field instead.

Both charts contain identical data. The left one is not merely less pretty: it supports a claim about the distribution that is simply false.

Empty buckets vanish unless you ask for them

A bin with no rows in it isn't drawn at all, so a histogram silently closes the gap and a bimodal distribution can look like one smooth hump. Right-click the bin pill → Show Missing Values and the empty buckets reappear as zero-height bars where they belong. Do this on every histogram; it costs one click and it is the difference between an honest shape and a misleading one.

Bin size changes the story

Too wide and you flatten real structure into one block; too narrow and you get noise. Try a few sizes before settling. Better still, choose New parameter… in the Size of bins box and show the control, so the reader can check for themselves whether a peak is real or an artefact of the bucket width you happened to choose.

Bins are always equal width and only work on numbers. For unequal bands — 0–100, 100–1,000, 1,000+ — or for bands with names, write an IF calculated field instead; you get the labels you want and the reader doesn't have to decode a bound. For date buckets use date parts, not bins.

🎯 Sets — a dynamic in/out membership

A set splits a dimension's members into In and Out. Unlike a group, a set can be defined by a rule and re-evaluates itself as the data changes.

Dynamic set — a rule

Right-click a dimension → Create → Set → Top tab.

  • Top 20 customers by Sales
  • Sub-categories with negative Profit
  • States above the average

Membership recalculates automatically as data or filters change.

Fixed set — a list

Select marks in the view → the set icon in the tooltip.

  • A hand-picked list of key accounts
  • Regions in a specific pilot programme

Stays exactly as you defined it until you edit it.

A set is just a TRUE/FALSE membership. That's why it works on Color, on Filters, and inside calculations without extra work.

The Create Set dialog — the same three tabs as a filter

Not a coincidence: a set is a saved answer to "which members?", and that's the question the filter dialog asks too.

TabDefines membership byRe-evaluates?
GeneralTicking members by hand, or Use allNo — a fixed list (unless you pick Use all)
ConditionA rule: SUM([Profit]) < 0, by field or by formulaYes
TopTop or bottom N by a measure, N optionally a parameterYes

A set is built on one dimension. There is no way to define a set across two fields directly — for that, either combine two sets (below) or write a boolean calculated field, which can reference anything.

🎛️ Using a set — five different jobs

A set is a TRUE/FALSE flag attached to every member, which is why it slots into so many places without extra work.

  1. On Filters

    Keep In, keep Out, or show both. Equivalent to a Top N filter, but defined once and reusable on every sheet — change the set and every view updates together.

  2. On Color, Rows or Columns — the comparison view

    You get two headers, In and Out. "Our top 20 customers versus everyone else" in one drag, no calculation, no second sheet. Right-click the pill → Show Members in Set to swap the In/Out headers for the actual member names while keeping everything else.

  3. Inside a calculation

    A set returns a boolean, so it drops straight into logic: IF [Top 20 Customers] THEN [Sales] END. That's how you build "revenue from our key accounts" as its own measure.

  4. As a Set Control — let viewers pick the members

    Right-click the set in the Data pane → Show Set. A card appears that looks like a filter but isn't: ticking members changes what's in the set, so a chart using the set on Color re-splits rather than losing rows. It's the right control whenever the comparison — these versus the rest — is the point.

  5. Driven by a Set Action

    Dashboard → Actions → Change Set Values. Clicking marks in one chart redefines the set and every view using it updates. A user selects any handful of products and instantly sees them against the rest — no parameter, no calculation.

Sets are computed early — the Top N trap, again

A dynamic set's membership is worked out at the same stage as FIXED LODs, before ordinary dimension filters. So "Top 20 Customers" filtered to the West region gives you the West members of the national top 20 — usually far fewer than twenty, and not the West's top customers at all.

Same symptom, same fix as a Top N filter: right-click the Region filter → Add to Context. See the order of operations.

Set Control vs filter card — pick by what should happen to the rest

A filter card removes the non-selected rows: totals shrink, percentages re-scale, the comparison disappears. A set control keeps every row and just re-labels them In or Out: totals stay whole and the selection is measured against the remainder. If the question is "how much of the business is this?", you want the set control.

➕ Combined sets

Select two sets in the Data pane, right-click → Create Combined Set. You get the standard set operations, and they answer questions that are awkward any other way.

Both sets must be built on the same dimension — you can combine two customer sets, but not a customer set with a product set. Combining across fields is a job for a boolean calculated field.

Two sets and one dropdown produce a churn list. The equivalent as calculations is a nested LOD and a boolean; as a combined set it is about forty seconds of work.

OperationReturnsUseful for
Union (all members)In either setEveryone who is a top customer or a recent customer
Intersection (shared)In both setsHigh spend and high frequency — your genuine best accounts
Except (A not B)In A but not BTop customers in 2016 who stopped buying in 2017 — churn
The churn analysis in three steps

Build "Customers in 2016" and "Customers in 2017" as two sets, then combine with Except. The result is your lapsed customers — a list a sales team can act on this afternoon. No calculations required.

Group vs set in one line: a group answers "these things belong together"; a set answers "these things meet a condition". If the answer could change when the data does, you want a set.

All five make a discrete field — which is the point

Groups, bins, sets, hierarchy levels and text-returning calculated fields all produce discrete dimensions. That's what makes them useful: a discrete field can be sorted, ticked in a filter list, given its own colour swatch, aliased and totalled. Reshaping a measure into one of these is very often the real answer to "why can't I filter/sort/group this number?" — see what blue and green gate.

🧠 Key intuitions

  • Always sort by value unless the categories have a natural order
  • Sort → By Field beats the quick-sort button for anything published
  • You can't sort a continuous axis — reverse it in Edit Axis instead
  • A sort is one order for the whole view — per-pane needs a nested sort or a rank calc
  • Show Missing Values on every histogram — empty buckets otherwise vanish
  • Aliases relabel; calculations still see the real value
  • Sets are computed before filter cards — the Top N trap all over again
  • Build hierarchies immediately — Product and Location take seconds
  • Groups are static; sets are dynamic
  • A set on Color is the fastest "these vs the rest" comparison there is
  • Bins turn measures into dimensions — that's how histograms happen
  • Combined sets answer churn and overlap questions with no calculations
  • If a rule defines it, don't hand-pick it — hand-picked lists go stale

🏆 Challenge: how concentrated is the customer base?

Build a view answering "what share of revenue comes from our top 10% of customers?" Create a dynamic Top N set driven by a parameter, put it on Color, and show the In/Out revenue split as a percentage. Then move the parameter from 5% to 50% and watch the curve. If the top 10% drive far more than 10% of revenue, the business depends on a small number of accounts: worth investing in keeping them, and worth knowing how much revenue walks out of the door if two of them leave.
