🔽 Filters

Filters control which data reaches a view. Tableau applies them in a set order, so combinations such as Top 10 and Region filters can produce unexpected results.

🗂️ Six kinds of filter

They look similar on the shelf but behave very differently — especially in what order they run.

Dimension filters

Keep or exclude category values. "Only East and West."

Measure filters

Filter on an aggregated number. "Only sub-categories with Sales over $100K." Runs after aggregation.

Date filters

Absolute ranges, relative ranges ("last 12 months"), or discrete periods.

Context filters

Promoted to run first, creating a temporary subset everything else works from.

Data source filters

Set on the Data Source page. Apply to every sheet in the workbook and are easy to forget.

Extract filters

Limit what gets pulled into an extract at all. The most efficient filter, because the data never arrives.

➕ Three ways to add one

// 1. Drag to the Filters shelf — full control
Drag [Region] from the Data pane onto Filters
→ a dialog opens for choosing values

// 2. From the view — fastest for exploring
Right-click a bar or mark → Keep Only
Right-click a bar or mark → Exclude

// 3. Show Filter — makes it interactive
Right-click [Region] in the Data pane → Show Filter
→ a filter card appears beside the view
Be careful with Exclude

Excluding specific members creates an "everything except these" rule. New values are included automatically when they appear in the data. Prefer explicitly keeping the values you want, or use a condition that updates as the data changes.

🧩 Which dialog you get — the field decides, not you

Tableau has four filter dialogs. It chooses one based on the field you drop, and you cannot switch dialog types after it opens. This is why a field may not offer a list of values to tick.

The rule in one line

Only a discrete (blue) field gives you a list of values to tick. A continuous (green) field represents a range, so Tableau offers a slider instead. Continuous fields do not offer checkboxes.

The pill's blue or green state determines the dialog. Convert the field to change the available filter controls.

discrete dimension
A tick list. Plus Wildcard, Condition and Top — the only dialog that offers rules as well as values.
continuous measure
A slider. Two handles and two number boxes. Special is where Null / Non-null lives.
any date field
A menu first. Pick a date part and you land in the tick-list dialog; pick Relative or Range and you get sliders.
measure → the prompt
Easy to click past. All values filters raw rows; Sum filters the totals in the view. Different answers.

Forcing the dialog you actually want

You want a tick list on a number. Four ways to get one, in the order you should try them.

Two conversions that sound the same and aren't

Dimension ↔ Measure determines whether Tableau aggregates a field. Discrete ↔ Continuous determines whether Tableau draws headers or an axis, and which filter dialog it opens. Postal Code should be both a dimension (so Tableau does not sum it) and discrete (so viewers can select individual codes).

Changing a pill in the view affects that view only. Changing the field in the Data pane sets the default for future sheets.

Groups, bins and sets are all discrete by construction, which is why they always give you a tick list. A FIXED LOD is a measure and behaves like one — unless you convert it to a dimension, in which case it becomes filterable as a list too.

🎛️ The discrete dialog's four tabs

All four tabs are active at once and combine with AND. A filter with both a General selection and a Top rule keeps only members that meet both conditions.

TabWhat it doesUpdates with new data?
GeneralTick and untick specific valuesNo — a fixed list
WildcardMatch text patterns — contains, starts with, ends withYes
ConditionFilter by a formula, e.g. SUM([Sales]) > 100000Yes

General — the tick list

  • Select from list is the default. Custom value list lets you type members that don't exist yet, so the filter is ready for them when they arrive.
  • Use all — a radio button above the list, and the one people miss. It means "everything, whatever that turns out to be" rather than "these specific ticked members". Choose it and new members are included automatically.
  • Exclude — a checkbox at the bottom right that inverts the whole selection.
  • The Null member appears in the list as its own entry when the field has any. Untick it to drop the blanks.
"Select from list" is different from "Use all"

Both options may look the same today. When a new sub-category appears, Use all includes it but a manually ticked list does not. Use Use all when the filter should include future values.

Wildcard — pattern matching on text

Only appears for string fields. Matching is case-insensitive.

Contains       // "chair" matches "Stackable Chair Mat"
Starts with    // "CA-" matches every Californian order ID
Ends with      // "Inc." matches corporate customers
Exactly matches// the whole string, but still a live rule

Condition — a rule per member

The condition is evaluated once per member of the field you are filtering, not once per row. Filtering Sub-Category by SUM([Sales]) > 100000 asks the question seventeen times, once for each sub-category, and keeps the ones that pass.

By field

Three dropdowns: a field, an aggregation, and a comparison. Covers most cases without typing anything.

Sales   ·  Sum  ·  >=  ·  100000

By formula

Must return a boolean and must be aggregated — a bare [Sales] > 100 is rejected.

SUM([Profit]) < 0
SUM([Sales]) > [Sales Threshold]

Because a condition can read a parameter, "show me only sub-categories above the threshold I choose" is one condition and one slider — no calculated field required.

Top — rank-based selection

By field:   Top  ·  10  ·  by  ·  Sales  ·  Sum
            Bottom · 5  ·  by  ·  Profit · Sum

// The N box accepts a parameter — click the dropdown and pick one.
// That is how a viewer-controlled "Top N" gets built.

By formula: Top  ·  10  ·  by  ·  SUM([Profit])/SUM([Sales])
Top filters run before ordinary dimension filters

Top N, set and conditional filters are computed before ordinary dimension filters, at the same point as FIXED LOD expressions. As a result, "Top 10 products in the East" can rank products nationally before filtering to East. A context filter changes that order. See the ladder below.

Prefer Condition and Top over General

The General tab creates a fixed list of members. Condition and Top filters define rules, so they continue to work as data changes. Use a rule when new values should be included automatically.

🎚️ Filtering a measure — the prompt that decides everything

When you drag Sales onto Filters, Tableau first asks how to aggregate it. The default is Sum, so choose a different aggregation if it better matches the question you want to answer.

"All values" — a row-level filter
Keep rows where
  [Sales] between 100 and 500

Tests each of the 9,994 order lines and throws away the ones outside the range. Then the survivors get aggregated. A sub-category can still total $2M, because it's made of many in-range lines.

Runs with the dimension filters, at step 5.

→
"Sum" — a measure filter
Keep marks where
  SUM([Sales]) between 100 and 500

Aggregates first, then tests each mark in the view. Nothing is removed from the underlying rows — whole bars simply disappear.

Runs as a measure filter, at step 7.

A measure filter depends on the view's level of detail

SUM(Sales) > 100K filters the marks in the current view. On a Category view, all three category totals may pass; after adding Sub-Category, smaller marks may fail. The filter is unchanged, but the level of detail is not. Use a FIXED LOD if the threshold must stay the same across views.

The four tabs of the range dialog

TabWhat it doesWorth knowing
Range of ValuesBoth ends set — a bandThe two boxes accept typed numbers; the slider is just a shortcut

Range filters exclude nulls

A range filter excludes rows where the field is null because nulls do not meet any comparison. If totals drop unexpectedly, switch to Special → All values to include those rows.

At Least and At Most are also the safer choice for anything published. A Range of Values filter pins both ends to the numbers that existed when you built it, so a genuinely new high value gets filtered out on the next refresh.

📅 Date filters — the menu before the dialog

Dates get their own first screen, because a date can be filtered in more ways than anything else. What you pick here decides both the dialog and whether the resulting pill is blue or green.

"Months" and "Month / Year" are different filters

Months is a date part with twelve members, January through December, pooled across all years. Selecting November includes November 2014, 2015, 2016 and 2017. Month / Year is a date value, so November 2017 is a separate entry. Choose the version that matches the time period you need.

Why "last 12 months" shows nothing on Superstore

A relative date filter is anchored to today by default. Because Superstore ends in December 2017, "Last 12 months" returns no rows. The empty view is expected, not an error.

Fix it with the Anchor setting at the bottom of the dialog. Set a fixed date from the data or use a parameter to set one workbook-wide "as of" date. A parameter is especially useful when live data arrives with a delay.

Relative date filters are the cheapest ones you can write

"Previous 2 years" hands the database a real date range, so it can use its index and read a fraction of the table. A discrete Year filter with 2016 and 2017 ticked usually cannot be optimised the same way. On a large table the difference is seconds versus minutes.

🎚️ Interactive filter cards

Right-click a filter pill → Show Filter. Then right-click the card itself to choose how it behaves.

Right-click the card itself to switch between these. The choice matters: a single-value list forces one region at a time; a multi-select lets people compare two. Pick the one that matches the question they'll ask.

Filter controls depend on the field type

Use "Only Relevant Values" for dependent filters

Without it, filtering to the West can still leave every state in the State filter, including states with no West data. With it, the card lists only relevant states. Right-click the card → Only Relevant Values.

🙈 Hide vs filter — they are not the same thing

Right-click a header and there is a Hide option sitting next to Exclude. They look interchangeable and they are not: Exclude removes the data, Hide only removes the label. Everything downstream still sees the hidden rows.

Both charts show three bars, but only one still includes the fourth in its calculations. Use Hide for a blank first period; use Exclude when the data should be removed from the results.

The case Hide exists for

Build year-over-year growth: YEAR on Columns, SUM(Sales) with a Percent Difference table calc. 2014 comes out blank — correct, there is nothing before it. Now suppose you want the chart to start at 2015.

Filter 2014 out and 2015 also goes blank because the calculation can no longer compare it with the prior year. Hide 2014 and 2015 keeps its result because the data remains in the calculation. The visible chart may look the same, but the calculation is different.

Document hidden members

A worksheet does not show that a header is hidden, which can make totals differ from visible rows. Restore hidden data with Analysis → Reveal Hidden Data or right-click the field → Show Hidden Data. Note intentional hidden values in the caption.

Hide only works on discrete headers — there is no way to hide part of a continuous axis, because an axis has no members to hide.

A related pair: Keep Only and Exclude in a mark's tooltip both write a real filter onto the Filters shelf. They are ordinary dimension filters with a friendlier entry point, and they use the General tab's fixed list — so the "Use all" warning above applies to them too.

🪜 Order of operations — the sequence filters run in

Tableau applies filters in a strict sequence. Use this ladder to diagnose results that differ from expectations, especially for Top N filters and table calculations.

  1. Extract filters
    Applied when the extract was built — the rows aren't even in the file
  2. Data source filters
    Workbook-wide, set on the Data Source page. Invisible from any worksheet
  3. Context filters
    Builds a temporary subset. Everything below sees only this. The one lever you have over the order
  4. FIXED LODs — and sets, Top N filters and conditional filters
    All computed here, before ordinary filter cards. This rung is the source of the Top N bug below, and of "why does my FIXED total ignore my filter?"
  5. Dimension filters
    Ordinary filter cards on categories and dates. Also where a measure filtered with All values lands, because that's a row-level test
  6. INCLUDE / EXCLUDE LODs
    Computed after the filter cards, so unlike FIXED they do respect them
  7. Measure filters
    Filters on aggregated values — SUM(Sales) > 100K. Nothing above this point can see them
  8. Forecasts and clusters
    Fitted to whatever survived. Change a filter and the model is refitted
  9. Table calculations
    Run on the finished view. They can only see what got this far — see Table Calculations
  10. Table calculation filters
    A filter on a table calc runs after the calc, so it hides marks without changing the calc's answer. Deliberately useful — see below
  11. Trend lines, reference lines, totals
    Computed from the marks that remain, which is why an average line moves when you filter
Use the ladder to diagnose results

When two results disagree, check their positions in the order of operations. A step can only use results from steps above it. This explains a FIXED total that ignores a Region card, a percent of total that changes after filtering, and a Top 10 that ranks a wider set than the visible data.

Two ways to move something: promote a filter to context to push it up to rung 3, or move a calculation down by rewriting a FIXED as an INCLUDE/EXCLUDE. There is no way to move a filter downwards, which is why context is the tool you reach for.

🎯 Context filters — the classic Top N bug

The situation

You want the top 10 products in the East region. You add a Top 10 filter on Product Name and a Region filter set to East. You get fewer than 10 products — sometimes only three or four — and they look wrong.

The only difference is when the region filter runs. Right-click it → Add to Context and it moves from rung 5 up to rung 3, which puts it ahead of the Top N at rung 4 — the grey pill on the Filters shelf is how you tell.

When to reach for a context filter

  • Top N within a subset — the case above, and by far the most common
  • A set whose membership should respect a filter — sets are computed at rung 4 too, so they have exactly the same problem
  • Percent of total within a subset — same logic
  • Making FIXED LODs respect a filter — context runs before them
  • Performance on very large data — occasionally, by shrinking the working set early

What a context filter actually does

A context filter does more than change priority. Tableau materialises the selected rows in a temporary table, then runs later steps against that table instead of the source. Later steps cannot use rows excluded by the context filter.

The temporary table is rebuilt whenever the context filter changes, so changing a context filter can be slower than changing an ordinary filter. Once it is set, later steps have less data to process.

Filter cards can be told to offer only values that exist in the context — right-click the card → All Values in Context. Useful when a context filter has narrowed the data but a downstream card is still listing members that can no longer appear.

Don't add everything to context

Context filters build a temporary table, which adds work whenever they change. Use them when the order of operations requires them, not by default.

🔗 Applying a filter to several sheets

By default a filter affects only its own worksheet. On a dashboard that's rarely what you want.

Right-click the filter pill → Apply to Worksheets →

  Only This Worksheet          // the default
  All Using This Data Source   // every sheet on this connection
  Selected Worksheets…         // pick exactly which — usually best
  All Using Related Data Sources
Prefer "Selected Worksheets"

"All Using This Data Source" also affects sheets you build later, including sheets that should remain unfiltered, such as a company-wide KPI card. Choose the target worksheets explicitly.

A filter applied to multiple sheets shows a small icon on the pill. On a dashboard, that one filter card now drives every connected chart — which is exactly how you build coordinated interactivity.

🧰 Other things that filter — and one that doesn't

The Filters shelf is not the only way rows leave a view, which is why "check the Filters shelf" is sometimes not enough.

Use a table-calc filter for "Top 10 of the current selection"

A Top N filter runs at rung 4, before filter cards, so it ranks the full data set. INDEX() <= 10 runs at rung 10, after filter cards, so it ranks the remaining data. Sort the view descending, put that calculation on Filters, and select True to create a Top 10 that responds to dashboard filters.

The trade-off is cost: the database still returns all 1,850 products and Tableau discards them at the end. Fine for a few thousand marks, wasteful for a few million.

A parameter is not a filter

Showing a parameter control does not change the view on its own. A calculation, a filter's Condition or Top tab, or a reference line must read the parameter. If the control has no effect, check that connection.

The upside of that indirection: a parameter can drive several unrelated things at once, and it can hold values that don't exist in the data — a target, a threshold, a scenario name. A filter can only ever offer what's there.

⚡ Filters and performance

Filters have a large effect on workbook performance, and some are much more efficient than others.

The width of each bar is the data still in play. A filter at the bottom of the funnel produces the same 17 marks as one at the top — it just makes the database read fifty million rows to get there.

ApproachCostNotes
Extract filterCheapestThe rows never enter the workbook
Data source filterVery cheapApplied before anything else
Dimension filter on a listCheapEfficient, especially on indexed columns
Context filterModerateBuilds a temporary table on each change
Measure filterModerateRequires aggregating first

Filter early, filter once

If a dashboard only shows the last two years, exclude older data in the extract rather than filtering it in every view. In general, remove unneeded data as early as possible so later steps have less work to do.

🧠 Key intuitions

  • Only discrete fields give you a tick list — green means a slider, always
  • Convert the field, not the dialog — Convert to Discrete, a bin, or a calculated string
  • Dimension/measure and discrete/continuous are two separate switches
  • The aggregation prompt is a real decision — All values filters rows, Sum filters marks
  • A range filter drops nulls — Special → All values brings them back
  • Order of operations explains most wrong numbers — learn the ladder
  • Top N, sets and conditions run at rung 4, before your filter cards
  • Top N + another filter = context filter, every time
  • Condition and Top beat the General tab — rules don't go stale
  • "Use all" ≠ everything ticked — only the first admits new members
  • Hide keeps the data, filter removes it — the fix for a blank first period
  • A relative date filter is anchored to today unless you say otherwise
  • Show Filter is what makes a dashboard interactive
  • Only Relevant Values stops viewers picking combinations with no data
  • Apply to Selected Worksheets, not "All Using This Data Source"
  • A parameter filters nothing until something reads it
  • Filter as early in the pipeline as possible
